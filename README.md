# Lecture-to-Summary — автоматическое создание конспектов лекций

**Lecture-to-Summary** — командный учебный Fullstack-проект для автоматической генерации структурированных конспектов лекций, статей и других учебных материалов с использованием искусственного интеллекта **GigaChat**.

Приложение объединяет пользовательский веб-интерфейс, серверную часть на **AdonisJS 6 (Node.js + TypeScript)** и интеграцию с внешним API языковой модели.

**Моя роль в проекте:** Backend Developer — разработка серверной логики, REST API, интеграция GigaChat и работа с данными.

---

## 🚀 Возможности приложения

- Загрузка учебных материалов в форматах PDF, DOCX и TXT.
- Ручной ввод текста для обработки.
- Автоматическое создание структурированных конспектов с помощью GigaChat.
- Выделение основных тезисов, терминов и определений.
- Генерация текста с поддержкой Markdown.
- Работа с историей сообщений и чатов.
- Прикрепление файлов к сообщениям.
- Редактирование и экспорт полученных конспектов через пользовательский интерфейс.
- Адаптивный интерфейс с поддержкой светлой и тёмной темы.

## 🏗 Архитектура приложения

Приложение построено по клиент-серверной архитектуре.

```text
                 Пользователь
                      |
                      v
             Frontend (Next.js)
                      |
                 HTTP / JSON
                      |
                      v
           Backend (AdonisJS 6)
                      |
          +-----------+-----------+
          |           |           |
          v           v           v
     Controllers   Lucid ORM   GigaChat Service
          |           |           |
          v           v           v
      REST API      SQLite     GigaChat API
          |
          v
     File Storage
```

**Принцип работы:**

1. Пользователь отправляет текст или прикрепляет учебный материал через интерфейс.
2. Frontend передаёт данные на backend через REST API.
3. Сервер обрабатывает запрос и при необходимости сохраняет данные.
4. Backend формирует запрос к GigaChat API.
5. Языковая модель генерирует ответ с учётом переданного контекста.
6. Сервер сохраняет результат обработки и возвращает данные frontend-приложению.
7. Пользователь получает результат в интерфейсе.

## 🔌 REST API

Основные маршруты приложения определены в `start/routes.ts`.

| Метод | Endpoint | Назначение |
|---|---|---|
| GET | `/api/chats` | Получение списка чатов |
| POST | `/api/chats` | Создание чата |
| GET | `/api/chats/:id` | Получение информации о чате |
| GET | `/api/messages` | Получение сообщений |
| POST | `/api/messages` | Создание сообщения и обработка запроса |
| POST | `/api/files` | Загрузка файла |
| GET | `/api/files/:id` | Получение файла |
| DELETE | `/api/files/:id` | Удаление файла |

Маршруты чатов и сообщений объявлены с использованием ресурсной маршрутизации AdonisJS. Фактическая доступность каждой операции зависит от методов соответствующего контроллера.

## ⚙️ Запуск backend

Для запуска потребуется Node.js, npm и настроенный доступ к GigaChat API.

**1. Клонирование репозитория**

```bash
git clone https://github.com/Atomcreater/lecture-to-summary.git
cd lecture-to-summary/Project/backend
```

**2. Установка зависимостей**

```bash
npm install
```

**3. Настройка окружения**

Создайте локальный файл `.env` на основе конфигурации проекта и укажите необходимые параметры приложения, базы данных и доступа к GigaChat API.

Не публикуйте реальные API-ключи и другие секреты в GitHub.

**4. Запуск сервера в режиме разработки**

```bash
npm run dev
```

**5. Проверка TypeScript**

```bash
npm run typecheck
```

**6. Запуск тестов**

```bash
npm test
```

Перед полноценным запуском также может потребоваться подготовка базы данных и применение миграций.
